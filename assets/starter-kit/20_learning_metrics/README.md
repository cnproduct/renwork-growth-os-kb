# 复盘、指标与持续学习

## KCS 解决环

`先搜索 → 复用 → 标记 → 在权限内修复 → 确认缺失后补充 → 用业务结果验证`。

## 演进环

Owner/KDE/Coach 定期聚合无结果、低分回答、赢输单、投诉、沉默和复购数据，执行合并、拆分、冲突裁决、过期处理、规则调整和评测更新。

## 四层指标

| 层 | 指标示例 |
|---|---|
| 内容 | 来源覆盖、过期、冲突、重复、AQI |
| 检索 | Top 5 命中、无结果、权限过滤、引用可达 |
| 回答/动作 | 事实一致、拒答准确、任务完成、审批合规 |
| 业务 | 响应时长、转化、复购、返工、采用和支持成本 |

## 三类队列 + 错误集

- 缺口：真实任务需要但知识缺失；
- 冲突：同一事实或规则不一致；
- 过期：达到复核日或来源变化；
- Error Book：只收录完成根因确认的重复失败，并关联回归用例。

## 红线

不能把每次负反馈直接写进提示词或公共知识；跨租户学习必须去标识、获授权并经审核。

## 必备输出
- [ ] 赢输单归因
- [ ] 沉默诊断
- [ ] 周报
- [ ] 知识更新候选
- [ ] 成熟度与质量指标

## 证据
待登记来源、抓取/签发日期和具体定位。

## 推荐动作
补充资料并提交对应负责人审核。

## 红线
未经核验与审批，不得对外承诺价格、MOQ、产能、交期、认证、案例、独家、账期或赔付。

## 待确认
来源、负责人、审批人、适用市场、有效期与公开范围。
